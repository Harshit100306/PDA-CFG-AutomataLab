Formal models

Each case study uses the model that matches its memory requirements.

MODEL 01

Balanced parentheses · DPDA

Push one marker for each opening parenthesis. Pop for each closing parenthesis. Accept only when input ends with the bottom marker exposed.

MODEL 02

Arithmetic syntax · CFG / PDA

Expression, term and factor nonterminals encode precedence. A CFG-to-NPDA construction uses the stack to expand grammar symbols and match terminals.

MODEL 03

Palindromes · NPDA

Nondeterministically guess the midpoint, push the prefix, then compare the suffix in reverse order by popping matching symbols.

Why a pushdown automaton?

Finite automata have a fixed number of states and cannot remember an arbitrarily deep nesting level or an arbitrarily long prefix for reverse comparison. A PDA adds a stack, enabling recognition of context-free structures. The arithmetic parser checks syntax only; it does not evaluate expressions, resolve identifiers, enforce types or detect runtime errors.
